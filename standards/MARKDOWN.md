# Markdown as a research interface

[Home](../README.md) / Standards / Markdown design

**Design aim:** let a reader locate the question, inspect the evidence, and recognize the limits with little navigation or visual effort.

The [E5 writing standard](WRITING.md) governs the argument. This page governs how the repository presents it.

## Page anatomy

| Position | Required job | Example |
| :--- | :--- | :--- |
| Title and breadcrumb | Name the subject and make the return path obvious | `Home / Course knowledge / Reading` |
| Opening | State the page's purpose or bounded finding | One or two sentences |
| Status, when consequential | Identify evidence class, review state, or scope | A compact two- or three-column table |
| Main body | Show the argument, comparison, sequence, or evidence | Short sections with descriptive headings |
| Closing links | Lead to sources, limitations, or the next research action | Two or three relevant destinations |

Avoid repeating the full repository policy on every page. Link to the maintained record. A brief analytical note does not need all five elements as separate sections.

## Choose the form for the reasoning

| Content | Preferred form | Limit |
| :--- | :--- | :--- |
| Explanation or inference | Connected prose | One main idea per paragraph; put its point early |
| Parallel evidence or comparison | Table | Usually 2–4 columns; concise cells with stable links |
| Order of work | Numbered sequence | Each step produces an inspectable result |
| Relationship or feedback | Small Mermaid diagram | Label conceptual relationships; provide a text explanation |
| Technical detail used by few readers | `<details>` disclosure | Keep conclusions, uncertainty, and review status visible |
| Quantitative result | Table or sourced figure | Include units, period, boundary, and observation type |

A table should expose distinctions. Do not turn a long paragraph into a crowded cell. A diagram should explain a relationship rather than decorate a title.

## Visual discipline

Use one H1 per page, a logical heading hierarchy, sentence-case headings, and consistent link labels. Use bold sparingly for a decision or key distinction. Leave space between sections. Avoid badges without a maintained meaning, emoji navigation, duplicated dashboards, and claims that polish establishes research quality.

Present unknowns as unknowns. Keep forecasts, scenarios, reported assertions, and measurements visibly distinct. A source locator belongs near the assertion it supports. Use accessible text labels; never rely on color alone.

## Before calling the page ready

| Check | Evidence of completion |
| :--- | :--- |
| Navigation | Relative links resolve; a reader can return to the parent page |
| Scan | Headings and tables reveal the argument and open questions |
| Fidelity | Compression has preserved qualifications, locators, and evidence classes |
| Rendering | Tables, diagrams, disclosures, and small-screen layout have been visually inspected |
| Maintenance | Counts and statuses come from maintained records or carry a clear as-of boundary |

Record rendering as unverified when no visual inspection occurred. A successful parser or link check establishes only its stated scope.
