# Reviewing and correcting this study

[Home](README.md) · [Starting notebook](docs/START-HERE.ipynb)

Begin with one sentence, its source and its locator. A useful correction identifies the exact wording, the source edition or URL, the relevant page, and why the evidence supports a narrower or different conclusion. You may use a GitHub issue or a pull request. Account creation and code changes are unnecessary for reading the notebooks.

For a source correction, distinguish a quotation error, translation concern, unsupported inference, missing context and new evidence. Keep personal contact information, unpublished feedback, raw course readings and transcripts out of public issues. Link to an official public source where possible. The repository does not offer a private channel for sensitive research data.

For a software change, explain the behavior before and after the change and include a relevant failure test. Run the checks described in [the method guide](methods/evidence-review/README.md), then refresh the repository assurance receipt. A passing test does not decide whether a source supports a claim.

The author owns final research and writing decisions. Human reviews must state who reviewed which version and what assistance was visible. AI may propose corrections and write tests; it cannot sign a human review. Assignment 2 v0.11 is preserved as an earlier checkpoint. Corrections to later interpretation belong in a dated record with a link to the original.
